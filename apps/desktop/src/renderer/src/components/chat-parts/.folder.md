# components/chat-parts

## 地位

Chat 与 Agent 消息内部按 AI SDK Part 类型拆分的呈现层。

## 逻辑

协调组件保留消息原始 Part 顺序，同时把正式回答前的 reasoning、过程说明、搜索、研究计划和自动工具聚合进单一“已工作”区块；完成后默认折叠，运行中展开，并继续使用各领域结构化 UI，不显示自动工具原始 JSON。等待用户回答、人工审批、失败与正式产物保留在区块外，避免隐藏必须处理的状态。所有工具组件都经 `@tessera/ai/react` 的单一类型边界调用 AI SDK `isToolUIPart` / `getToolName`，不再各自解析 `tool-*` 字符串；联网搜索工具按 AI SDK provider-executed `output.action` / `output.sources` 契约聚合真实查询、打开页面与 URL 来源，同时兼容旧供应商结果数组，并以 HTTPS 图片请求加载来源站点图标；等待用户回答与研究计划使用受限、具名且经过运行时校验的专用卡片，网页深读、证据登记、来源推荐和完成检查则按标准 Tool Part 的真实输入输出聚合为研究进度，不读取模型旁白，并通过窄 IPC 读取增量笔记或按用户选择保存来源；最终正文后的 `data-follow-up-questions` 以“继续探索”呈现，点击只把问题带入输入框，不自动发送；只有领域 Reader 返回的失败才计为不可用来源并展示原因，SDK 工具协议错误不伪装成网页；创建文档、创建项目、移动文档和结构检查按同一消息聚合为 Operation 活动，只展示对象名称、数量和状态，同时保留 AI SDK 标准审批；其余通用工具通过设计系统 Tool Chips 映射原始状态、资源和状态；每个组件只解释自己的流式状态，不改写 Transport 事件。

## 约束

- 保留 `UIMessage.parts` 的边界与顺序，不把多个正文 Part 拼成一个不可区分的字符串。
- 增量中的思考、正文与工具必须提供明确的 `aria-busy` 状态。
- “已工作”只收纳信息性自动过程；请求用户输入、人工审批、拒绝、失败和正式回答不得因折叠而不可见。
- 没有正文的 reasoning 生命周期只参与整轮工作阶段，不逐条刷屏；正文只在供应商明确返回文本时出现，并共享安全 Markdown 渲染器；不执行原始 HTML，也不补写或占位供应商未返回的思维链。
- Markdown 渲染、思考过程、来源标签和工具状态不访问 Electron 或业务存储。
- 来源站点图标只允许 HTTPS 图片，使用无 Referer 的懒加载请求；站点与远端回退均失败时必须保留通用图标。

## 成员清单

- `chat-markdown.tsx`：为正文和 reasoning 统一渲染 GFM、链接、列表、表格与代码块，并提供常规/紧凑密度。
- `chat-markdown.test.tsx`：验证思考文本中的 Markdown 语义和外链安全属性。
- `text-part.tsx`：逐个渲染 Markdown 正文 Part，并标记正在生成的末尾光标。
- `reasoning-part.tsx`：呈现由协调层选出的供应商真实 reasoning 阶段；非空摘要以无左侧时间线、限高独立滚动区紧凑渲染 Markdown，流式时按用户阅读位置跟随末尾，空摘要交由整轮工作阶段表达。
- `reasoning-part.test.tsx`：验证长思考内容无左侧时间线、最大高度、独立滚动、可访问状态与完成态空摘要阶段外壳。
- `source-part.tsx`：汇总、去重并呈现 URL 与文档来源。
- `follow-up-questions-part.tsx`：校验并呈现回答后的 2–4 个引申问题；点击只带入输入框，不自动提交。
- `web-search-part.tsx`：按 AI SDK 标准 action/sources 与旧结果数组聚合同一消息的真实联网查询、打开页面和 URL 来源，呈现带真实网站 favicon、失败回退与 256px 独立滚动上限的可展开搜索轨迹。
- `web-search-part.test.tsx`：验证 Responses 标准输出、旧联网结果、限高滚动、来源去重、安全 URL、HTTPS favicon 策略与供应商内部调用标识隔离。
- `tool-part.tsx`：经 AI SDK 标准 Tool Part 守卫把动态或具名工具映射为紧凑 Tool Chips，并呈现访问资源、输入、执行、完成、拒绝、失败原因及内容领域写操作的紧凑审批。
- `tool-part.test.tsx`：验证 AI SDK 状态、访问资源、输入详情、失败原因和内容领域审批正确进入 Tool Chips。
- `content-operation-part.tsx`：把创建文档、创建项目、移动文档和结构检查聚合为面向对象名称的 Operation 活动，并复用原生审批区。
- `content-operation-part.test.tsx`：验证聚合、完成折叠、内部 ID 隐藏与人工审批保留。
- `task-error-part.tsx`：按版本化稳定错误码呈现随助手消息持久化的整轮失败标题与原因，只在 `retryable` 为真时提供 AI SDK 原生重新生成入口，并兼容旧消息。
- `task-run-activity.tsx`：以 3×3 像素网格与文字 shimmer 呈现运行中的整轮“已工作”计时，完成后静止并默认折叠；展开内容保持无左侧竖线的开放布局。
- `task-run-activity.test.tsx`：验证像素网格、文字 shimmer、无左侧竖线、整轮耗时与完成折叠状态。
- `user-input-part.tsx`：校验并呈现 Agent 等待用户回答的结构化问题，支持单选、多选、文本、跳过与已回答摘要。
- `research-plan-part.tsx`：校验并呈现研究目标、范围、交付物与问题列表，不信任工具传入的原始结构。
- `research-activity-part.tsx`：聚合网页深读、不可用来源、证据登记、来源推荐、问题覆盖与完成检查的真实领域进度，并提供增量笔记预览与用户选择保存。
- `research-activity-part.test.tsx`：验证进度只来自标准工具结果，并区分已发现、已阅读、不可用、证据、推荐和部分完成。
- `task-interaction-parts.test.tsx`：验证问答与研究计划工具的运行时校验、专用卡片及已完成摘要。
- `agent-change-review.tsx`：写工具冻结候选内容的 Markdown 结果预览、逐行高亮 Diff 与批准/拒绝操作。

## 触发器

AI SDK Part 类型、流式状态或成员变化时更新本文。
