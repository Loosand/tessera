# components/chat-parts

## 地位

Chat 与 Agent 消息内部按 AI SDK Part 类型拆分的呈现层。

## 逻辑

协调组件按消息中的原始 Part 顺序渲染思考、正文和工具状态；同一回复中没有正文的多个 reasoning 生命周期聚合成一个整体阶段，非空 reasoning 仍按原始 Part 呈现；联网搜索工具按 AI SDK provider-executed `output.action` / `output.sources` 契约聚合真实查询、打开页面与 URL 来源，同时兼容旧供应商结果数组，并以 HTTPS 图片请求加载来源站点图标；等待用户回答与研究计划使用受限、具名且经过运行时校验的专用卡片，其余通用工具通过设计系统 Tool Chips 映射原始状态、资源和输入详情；每个组件只解释自己的流式状态，不改写 Transport 事件。

## 约束

- 保留 `UIMessage.parts` 的边界与顺序，不把多个正文 Part 拼成一个不可区分的字符串。
- 增量中的思考、正文与工具必须提供明确的 `aria-busy` 状态。
- 没有正文的 reasoning 生命周期必须保留整体紧凑阶段外壳，但不得逐条刷屏；正文只在供应商明确返回文本时出现，并共享安全 Markdown 渲染器；不执行原始 HTML，也不补写或占位供应商未返回的思维链。
- Markdown 渲染、思考过程、来源标签和工具状态不访问 Electron 或业务存储。
- 来源站点图标只允许 HTTPS 图片，使用无 Referer 的懒加载请求；站点与远端回退均失败时必须保留通用图标。

## 成员清单

- `chat-markdown.tsx`：为正文和 reasoning 统一渲染 GFM、链接、列表、表格与代码块，并提供常规/紧凑密度。
- `chat-markdown.test.tsx`：验证思考文本中的 Markdown 语义和外链安全属性。
- `text-part.tsx`：逐个渲染 Markdown 正文 Part，并标记正在生成的末尾光标。
- `reasoning-part.tsx`：呈现由协调层选出的供应商 reasoning 阶段；非空摘要以限高独立滚动区紧凑渲染 Markdown，流式时按用户阅读位置跟随末尾，空摘要只保留不可展开的整体“思考中 / 思考完成”外壳。
- `reasoning-part.test.tsx`：验证长思考内容的最大高度、独立滚动、可访问状态与完成态空摘要阶段外壳。
- `source-part.tsx`：汇总、去重并呈现 URL 与文档来源。
- `web-search-part.tsx`：按 AI SDK 标准 action/sources 与旧结果数组聚合同一消息的真实联网查询、打开页面和 URL 来源，呈现带真实网站 favicon 与失败回退的可展开搜索轨迹。
- `web-search-part.test.tsx`：验证 Responses 标准输出、旧联网结果、来源去重、安全 URL、HTTPS favicon 策略与供应商内部调用标识隔离。
- `tool-part.tsx`：把动态或具名工具 Part 映射为紧凑 Tool Chips，并呈现访问资源、输入、执行、完成、拒绝与失败原因。
- `tool-part.test.tsx`：验证 AI SDK 状态、访问资源、输入详情与失败原因正确进入 Tool Chips。
- `user-input-part.tsx`：校验并呈现 Agent 等待用户回答的结构化问题，支持单选、多选、文本、跳过与已回答摘要。
- `research-plan-part.tsx`：校验并呈现研究目标、范围、交付物与问题列表，不信任工具传入的原始结构。
- `task-interaction-parts.test.tsx`：验证问答与研究计划工具的运行时校验、专用卡片及已完成摘要。
- `agent-change-review.tsx`：写工具冻结候选内容的 Markdown 结果预览、逐行高亮 Diff 与批准/拒绝操作。

## 触发器

AI SDK Part 类型、流式状态或成员变化时更新本文。
