# components/tasks/messages

## 地位

任务消息协调、流式 Part 呈现与单次运行检查目录。

## 逻辑

`ChatMessage` 保留原始 Part 顺序，识别正式回答边界并把自动过程聚合为不读取 reasoning 正文的实时 Progress；具体消息 Part 下沉到 `chat-parts/`，运行详情通过窄 IPC 按需读取 Progress、实际 Execution Context，以及单独分层的指标、压缩、turn/tool/terminal 与凭据剔除供应商错误正文。

## 约束

- 展示层不重排、拼接或伪造供应商未返回的消息内容。
- 人工审批、等待输入、失败和正式产物不得隐藏进自动过程折叠区。
- 运行检查只呈现已上报或可推导的事实，缺失值不伪造为零；原始诊断只允许有界供应商错误正文，API Key / Authorization、请求载荷、Header 和堆栈仍不可见。

## 成员清单

- `chat-message.tsx`、`chat-message.test.tsx`：消息 Part 协调、正式回答边界、事实活动标签/动作数与回归测试。
- `chat-parts/`：按 AI SDK Part 类型拆分的流式呈现单元。
- `run-inspection-popover.tsx`、`run-inspection-popover.test.tsx`：用户 Progress、实际模型/Skill/工具/文件/Web/MCP 执行上下文，以及 Token、压缩、turn/tool/terminal、耗时、供应商原始错误与诊断测试。

## 触发器

消息协调、Part 边界、运行检查或成员变化时更新本文。
