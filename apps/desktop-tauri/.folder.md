# desktop-tauri

## 地位

Tessera 的 Tauri v2 对照壳，用于在不复制 renderer 组件的前提下比较系统 WebView 与 Electron 的实际体验。

## 逻辑

Vite 入口先安装 `window.tessera` 窄桥和单一 Tauri 事件监听，再动态加载 `apps/desktop` 的共享 renderer；`package.json` 显式声明对 `@tessera/desktop` 的 workspace 依赖，使 Turbo 把 renderer 变化纳入 Tauri 构建哈希。Rust 端只通过严格频道 allowlist 接受 `desktop_invoke` 与 `desktop_send`，首期提供无副作用空态和明确的未支持错误。

## 约束

- 不复制 Electron renderer 组件，始终从 `apps/desktop/src/renderer/src/` 加载同一入口。
- renderer 只能使用 `@tessera/desktop-bridge` 提供的 `DesktopApi`，不得直接获得文件、Shell 或数据库能力。
- Tauri capability 只开放事件监听、窗口显示和标题栏拖动所需的最小能力。
- 与 Electron 使用不同的 bundle identifier 和数据目录，避免两个对照应用并发写同一状态。

## 成员清单

- `src/`：安装 Tauri transport、总事件监听和标题栏适配的浏览器启动层。
- `src-tauri/`：Tauri v2 Rust 壳、频道 allowlist、窗口生命周期和最小 capability。
- `.gitignore`：忽略 Tauri 前端产物、自动生成的 capability schema 与 Cargo target。
- `index.html`：Tauri WebView 的 HTML 入口。
- `package.json`：前端、Tauri CLI 与工作区命令。
- `tsconfig.json`：Tauri 启动层和共享 renderer 的浏览器类型检查。
- `vite.config.ts`：共享 renderer 的 Vite、React 与 Tailwind 构建配置。

## 触发器

壳层边界、共享 renderer 入口、Tauri transport、构建命令或目录成员变化时更新本文。
