# docs/research

## 地位

保存与 Tessera 产品和架构决策直接相关的外部源码研究档案。

## 逻辑

每个被研究项目使用独立子目录，先固定源码版本和研究方法，再按领域记录实现链路、设计取舍、风险与可借鉴结论；
已经形成 Tessera 决策的内容再同步到 `docs/architecture/`，研究档案本身不充当 Tessera 的实现事实源。

## 约束

- 结论必须能追溯到固定提交的源码、测试、配置或项目文档。
- 区分源码事实、研究推断和对 Tessera 的建议，不能把外部项目能力写成 Tessera 已实现能力。
- 对照 Tessera 时使用「已实现」「部分实现」「规划」「未开始」标记状态。
- 不复制第三方大段源码；只记录必要的路径、符号、数据流和少量接口形态。

## 成员清单

- `eigent/`：Eigent 的 AI、Agent、工作区、扩展能力与交互设计源码研究。
- `pi/`：Pi coding-agent 的 Agent Kernel、产品会话、上下文、工具、扩展、模型与嵌入协议源码研究。

## 触发器

新增或删除研究项目、证据约定、状态标记或研究结论转化流程时更新本文。
