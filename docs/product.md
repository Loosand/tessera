# Tessera 产品边界

> 状态：统一自然对话方向已确认；本地工作区与编辑基础已实现，Skill、联网研究、工作区 Agent 与 Diff 写入部分实现；内容存储仍在探索，暂以托管内容库混合方案为实验基线，同时保留数据库正文和完全开放外部工作区候选；
> 开源许可证尚未确定。

## 目标

Tessera 面向需要长期阅读、研究和写作的个人用户。产品需要同时满足两条路径：

1. 不配置模型时，用户可以在本地完成 Markdown 阅读、整理和写作。
2. 接入 AI 后，用户可以在同一条自然对话中让统一 Agent 采集资料、理解来源、调用 Skill、创建文档、核查声明并整理本地项目。

当前阶段两条路径使用同一份可读、可导出的本地 Markdown，AI 输出不只停留在对话记录中。最终正文事实源是否
继续采用本地文件仍待存储探索决定；无论选择哪种方案，都必须提供明确的导入、导出、备份和迁移路径，不能形成
无法辨认权威副本的数据库/文件双写。

用户不需要选择 Chat/Agent 或手动组合联网、工具和思考开关。简单请求直接回答，复杂请求由每轮运行策略在
已授权范围内调用能力；对话可以从无工作区开始，随后附加当前文档、创建 Markdown 产物或关联新的本地项目。

## 产品模型

Tessera 使用 `Input -> Process -> Output` 描述从问题到文章的过程。Skills 为三个阶段提供可复用工作流，
权限和审计规则约束每一次外部访问与文件修改。

| 阶段 | 用户目标 | 主要能力 | 当前状态 |
| --- | --- | --- | --- |
| Input | 收集已有材料，或围绕问题主动研究 | 本地文件、网页、订阅源、PDF、音视频转录、Web Search、正文提取 | 本地 Markdown 已实现，其余规划 |
| Process | 读懂材料并形成可追溯的判断 | 阅读、划线、批注、跨材料问答、比较、事实核查、引用 | 规划 |
| Output | 写成可以继续修改和交付的文档 | 手动写作、提纲、续写、改写、审稿、引用检查 | 编辑基础已实现，AI 协作规划 |

### Input：采集与主动研究

Input 包含两种行为：

1. 用户提供材料：打开本地工作区，导入文件，剪藏网页，订阅更新，记录划线和笔记。
2. Agent 主动研究：拆分问题，多轮搜索，抓取正文，去重并补充缺失来源，最后将材料保存到当前项目。

主动研究不能只返回搜索摘要。每份材料需要保留来源 URL、作者、发布时间、抓取时间和原文，后续结论才能回到
证据位置。

### Process：阅读与理解

Process 处理来源之间的关系，包括：

- 区分原文事实、来源观点、用户判断和 Agent 推断；
- 比较不同来源的一致、冲突和证据强弱；
- 从划线和笔记中整理主题与待验证问题；
- 为具体声明寻找支持证据和反例；
- 保留从文章段落到原文片段的引用路径。

数据关系优先服务可追溯性，不提前建设脱离真实使用场景的通用知识图谱：

```text
来源 -> 原文片段 -> 用户批注 -> 事实声明 -> 推断 -> 文档段落
```

### Output：写作

Output 聚焦文本，不以生成格式数量作为目标。近期范围包括研究报告、长文、评论、公众号文章、摘要、提纲和
普通 Markdown 文档。

用户可以从空白文档开始手写，也可以从研究任务生成提纲或初稿。两种方式共享编辑、保存、撤销、历史和引用协议。
没有 AI 时，编辑器仍需完整支持日常写作；接入 AI 后，Agent 围绕选区、章节、整篇文档和相关材料提供建议。

## 写作原则

- 编辑器是主要工作表面，对话面板是按需出现的辅助表面。
- AI 建议以选区操作、行内建议或 Diff 表达，不能静默替换正文。
- 接受建议后，内容成为普通 Markdown，可以继续手动修改。
- 保存、撤销和外部修改冲突不区分人工内容与 AI 内容。
- 文章必须允许从引用位置回到来源；无法确认的推断需要明确标记。
- 中文写作质量需要通过参考样本、结构约束、事实检查和修订评测持续验证，不能只依赖单次 Prompt。

## Skills

Skill 可以作用于任一阶段，例如站点采集、深度研究、事实核查、辩证分析或公众号写作。Skill 文件应当可阅读、
可修改、可 Fork，并声明所需工具和资源权限。

当前先以内置“研究”和“写作”验证标准 `SKILL.md`、渐进式加载、任务持久化和权限隔离；界面中的“问答”表示不加载 Skill。写作正文已经覆盖写作动作判断、材料事实边界、文体选择、受控修订和分层质检，但独立质量评测尚未完成；研究正文仍会继续随真实任务打磨。

近期顺序是：

1. 提供少量官方 Skill，覆盖研究、核查和长文写作。
2. 支持本地发现、安装、版本和工作区作用域。
3. 建立公开 Registry，允许社区提交和改进 Skill。
4. 通过固定任务、引用正确率和人工反馈评估版本质量。

付费市场、榜单和分成不属于当前范围。若后续引入，它们不能改变本地 Skill 可检查、可导出和可修改的基本属性。

## 数据与权限

- Markdown 和附件保存在用户选择的工作区中。
- 当前混合实验允许用户选择本地内容库，以可见的“未归档”工作区承接尚未分类的 Agent 产物，并继续登记内容库外的普通目录；它不是最终存储承诺。
- 当前实现中 SQLite 保存会话、资源关系、可重建索引、运行状态与审计，不保存已批准正文的唯一副本；数据库正文候选只有在独立评审和迁移设计完成后才能改变这条边界。
- 外部搜索、网页抓取和模型调用需要明确的网络边界。
- 调用外部模型时，界面需要说明接收方和发送范围。
- Agent 的读取、联网、执行和写入权限分别判断，Skill 声明不等于用户批准。
- Agent 文件修改先生成可审查 Diff，批准后才写入，并保留审计记录。
- 架构允许接入用户自己的 API Key、本地模型和后续离线流程。

## 范围

### 产品范围

- 本地 Markdown 工作区与人工写作；
- 网页、订阅源、文档和音视频内容的采集与阅读；
- 主动研究、跨材料理解、事实核查和引用；
- 围绕文档的 AI 写作辅助；
- 可安装、可修改的 Skills；
- 权限、Diff、审计和可移植数据。

### 当前不建设

- Slides、视频和交互网页的专用编辑器；
- 以团队协作为前提的云端文档服务；
- 只能在 Tessera 内读取的正文格式；
- 未经确认的后台数据上传和 Agent 写入；
- 与实际功能无关的通用插件市场。

其他格式可以在真实需求出现后通过导出器或 Skill 接入，不要求 Tessera 持有对应的完整创作器。

## 验收问题

产品和技术方案至少需要回答以下问题：

1. 不配置 AI 时，用户能否稳定完成打开、阅读、编辑、保存和导出？
2. 研究结果是否覆盖关键来源，并能解释搜索范围与遗漏？
3. 结论和文章段落能否回到对应原文？
4. AI 修改是否可理解、可拒绝、可撤销？
5. 用户能否知道哪些数据离开了本机，以及发送给了谁？
6. Skill 升级后，质量变化能否通过固定任务和历史结果比较？
