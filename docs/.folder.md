# docs

## 地位

记录 Tessera 的产品边界与跨目录架构。

## 逻辑

`product.md` 说明产品范围和验收问题，`architecture.md` 说明系统边界，`architecture/` 记录需要跨目录维护的
具体机制。视觉和交互事实源保留在根目录 `design.md`。

## 约束

- 文档以实际代码和配置为证据。
- 规划能力必须显式标记，不能写成已实现事实。
- 产品文档定义范围，架构文档解释实现边界，不重复维护成员清单。

## 成员清单

- `product.md`：产品目标、IPO、写作原则、Skills、数据边界与范围。
- `architecture.md`：系统边界、运行时和包职责。
- `architecture/`：编辑器、数据库等跨目录机制。

## 触发器

产品范围、系统边界、架构文档入口或状态标记变化时更新本文。
