## 目标

从现有「新任务」界面出发，依次交付四层能力：

1. 安全、可持久化的供应商运行时。
2. 不读取工作区的普通 AI 对话。
3. 可读取工作区但不可修改文件的 Agent。
4. 通过 Diff、人工批准和审计记录修改 Markdown 的 Agent。

这个顺序是依赖关系，不是四套独立产品。普通对话和 Agent 共用消息界面、供应商配置与流式协议；Agent 只在用户明确进入相应模式并授予权限后增加工具能力。

## 固定边界

- 渲染层不持有供应商密钥，不直接请求模型，也不直接访问文件系统。
- 普通对话默认只发送用户显式输入和当前会话历史，不读取工作区、当前文档或剪贴板。
- 当前选中 Skill 通过 AI SDK instructions 注入，只改变任务方法；Skill 声明不授予联网、工作区或写入权限。
- Agent 的工作区根目录由主进程注入，模型不得通过参数自行选择或扩大目录。
- 只读 Agent 不暴露写入、删除、重命名、Shell 或任意网络工具。
- 可写 Agent 第一版只创建或更新 Markdown，不删除或重命名文件。
- 任何 Agent 写入都必须先展示 Diff；批准前不改变磁盘，拒绝后不得继续尝试同一写入。
- 每次工具调用设置路径、结果大小、步骤数、时间和 token 上限。
- 正文继续以 Markdown 为事实源；数据库只保存会话、索引、运行状态和审计信息。

## 目标数据流

```text
用户输入
  -> 渲染层消息界面
  -> 类型化 IPC
  -> 主进程解析供应商与模型
  -> AI SDK streamText / ToolLoopAgent
  -> 文本增量或工具事件
  -> 渲染层呈现

可写 Agent 的文件提案
  -> 主进程冻结路径、基准版本和候选内容
  -> 渲染层展示 Diff
  -> 用户批准或拒绝
  -> 主进程重新校验磁盘版本
  -> 原子写入或报告冲突
  -> 记录审计事件
```

- [ ] 在主进程使用 AI SDK `streamText` 发起生成，并用 `AbortController` 实现停止生成和窗口关闭清理。
- [x] 为 React `useChat` 实现 Electron `ChatTransport`；渲染层不使用会直接请求外网的 transport。

## M2：只读工作区 Agent

目标：用户明确选择 Agent 模式后，模型可以分步骤读取并理解工作区，但不能改变文件。

### 工具与编排

- [x] 使用 AI SDK `ToolLoopAgent` 实现工具循环，并通过 `inputSchema` 校验入口输入。
- [x] 第一批工具限制为 `list-workspace-files`、`read-workspace-file`、`search-workspace-text` 和 `read-current-document`。
- [x] 主进程为每次运行注入工作区根目录；所有工具统一执行路径归一化、目录穿越和符号链接逃逸检查。
- [x] 限制单文件大小、搜索结果条数、工具输出体积、总步骤数、总耗时和 token 用量；达到限制时返回结构化结果。
- [x] 将 AI SDK 工具增量通过泛型 `AgentRuntime` 端口输出，保留推理、工具、审批、完成、失败和取消的 `UIMessageChunk` 语义。

### 界面与可见性

- [x] 在提交前明确展示本次 Agent 可读取的工作区和数据范围。
- [x] 消息中展示工具名称、状态、读取文件和失败原因；冗长结果不展开到消息正文，但实际访问的相对路径保持可见。
- [x] 回答中的工作区结论支持相对 Markdown 链接跳转到文件与源码行号。
- [x] Agent 模式与普通对话模式使用任务级明确状态，不根据提示词自动提升权限；缺少工作区或工具能力时阻止发送而不降级。

### 验收门槛

- [ ] Agent 能通过多次工具调用回答跨文件问题，并为关键结论给出可验证的文件来源。
- [x] `../`、绝对路径、工作区外符号链接、超大文件和超量搜索结果均被主进程拒绝或截断为结构化受限结果。
- [x] 只读运行时没有可达的写入、删除、重命名、Shell 和任意网络接口。
- [ ] 停止 Agent 后，正在执行的工具和后续步骤都能终止，并产生完整的结束事件。

- [x] 在审批卡片中展示目标路径、Markdown 渲染结果、逐行高亮 Diff、增删统计与基准版本。

## 建议交付顺序

每项保持为可单独审查和回退的变更：

1. 供应商安全存储、配置 IPC 与默认模型解析。
2. 流式生成 IPC、取消和模拟供应商测试。
3. 对话界面、通用会话模型与历史恢复。
4. 只读 Agent 工具、路径安全和文件引用。
5. Diff 审批、版本复核、原子写入和审计。
6. 上下文控制、成本可见性、评测集和可靠性收尾。

M0 验收前不开始真实对话接入；M1 的流式协议稳定前不接工具事件；M2 的路径与资源限制通过测试前不开放写工具；M3 的 Diff、批准和冲突处理缺少任一项时，不允许 Agent 修改磁盘。
