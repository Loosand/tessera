## 目标

从现有「新任务」界面出发，依次交付四层能力：

1. 安全、可持久化的供应商运行时。
2. 不读取工作区的普通 AI 对话。
3. 可读取工作区但不可修改文件的 Agent。
4. 通过 Diff、人工批准和审计记录修改 Markdown 的 Agent。

这个顺序是依赖关系，不是四套独立产品。普通对话和 Agent 共用消息界面、供应商配置与流式协议；Agent 只在用户明确进入相应模式并授予权限后增加工具能力。

## 固定边界

- 渲染层不持有供应商密钥，不直接请求模型，也不直接访问文件系统。
- 普通对话默认只发送用户显式输入和当前会话历史，不读取工作区、当前文档或剪贴板。
- Agent 的工作区根目录由主进程注入，模型不得通过参数自行选择或扩大目录。
- 只读 Agent 不暴露写入、删除、重命名、Shell 或任意网络工具。
- 可写 Agent 第一版只创建或更新 Markdown，不删除或重命名文件。
- 任何 Agent 写入都必须先展示 Diff；批准前不改变磁盘，拒绝后不得继续尝试同一写入。
- 每次工具调用设置路径、结果大小、步骤数、时间和 token 上限。
- 正文继续以 Markdown 为事实源；数据库只保存会话、索引、运行状态和审计信息。

## 目标数据流

```text
用户输入
  -> 渲染层消息界面
  -> 类型化 IPC
  -> 主进程解析供应商与模型
  -> AI SDK streamText / ToolLoopAgent
  -> 文本增量或工具事件
  -> 渲染层呈现

可写 Agent 的文件提案
  -> 主进程冻结路径、基准版本和候选内容
  -> 渲染层展示 Diff
  -> 用户批准或拒绝
  -> 主进程重新校验磁盘版本
  -> 原子写入或报告冲突
  -> 记录审计事件
```

## M0：供应商运行时

目标：用户配置一次供应商后，重启应用仍可选择模型；后续对话和 Agent 不再各自处理密钥。

### 配置与存储

- [ ] 定义供应商配置契约：供应商类型、显示名称、Base URL、默认模型、启用状态和凭据引用。
- [ ] 在主进程使用系统安全能力加密保存 API Key；数据库或配置文件只保存非敏感字段和凭据引用。
- [ ] 增加读取、保存、删除、测试连接和列出可用模型的窄 IPC；返回渲染层的对象不得包含完整 API Key。
- [ ] 将设置页中的供应商草稿从组件局部状态提升为持久化配置状态，并区分「已保存」「有未保存修改」「连接测试中」和「连接失败」。
- [ ] 为默认供应商和默认模型建立唯一解析规则；配置失效时不静默切换到其他供应商。

### 运行时

- [ ] 在主进程增加统一的模型解析器，根据配置创建 AI SDK `LanguageModel`。
- [ ] 对请求日志、IPC 错误和诊断信息做密钥、Authorization Header 与敏感查询参数脱敏。
- [ ] 为缺少密钥、Base URL 非法、模型不存在、供应商超时和限流提供可操作错误。

### 验收门槛

- [ ] 保存供应商、退出并重启应用后，启用状态、Base URL、模型列表和默认模型可恢复。
- [ ] 用户可以从已配置供应商直接选择模型；未配置状态有明确入口，不展示伪造的可用模型。
- [ ] 渲染进程状态、开发者日志和 IPC 响应中均找不到完整 API Key。
- [ ] 使用模拟供应商覆盖成功、超时、限流、鉴权失败和畸形响应测试。

## M1：普通 AI 对话

目标：把「新任务」从本地输入界面接成可停止、可恢复的多轮流式对话，同时保持良好的手动输入和编辑体验。

### 流式协议

- [ ] 在 `packages/contracts` 定义开始、文本增量、完成、失败和取消事件，包含稳定的会话 ID、消息 ID、请求 ID 和递增序号。
- [ ] 在主进程使用 AI SDK `streamText` 发起生成，并用 `AbortController` 实现停止生成和窗口关闭清理。
- [ ] 为 React `useChat` 实现 Electron `ChatTransport`；渲染层不使用会直接请求外网的 transport。
- [ ] 处理重复事件、乱序事件、订阅释放、渲染进程刷新和中途取消，避免消息重复或请求悬挂。

### 会话与界面

- [ ] 提交首条消息后，将居中的任务输入框平滑转换为消息列表和底部固定输入框。
- [ ] 支持多行输入、选区编辑、撤销、粘贴、中文输入法、键盘发送与鼠标发送；流式生成期间仍允许整理下一条输入。
- [ ] 渲染 Markdown、代码块和链接，并提供复制、停止、重试和重新生成。
- [ ] 明确显示当前供应商与模型；切换模型只影响下一次生成，并记录到对应消息。
- [ ] 确定通用任务会话模型：普通对话允许没有工作区，Agent 会话可以绑定工作区；通过前向迁移落地，不重写已有迁移。
- [ ] 持久化消息内容、消息 parts、供应商、模型、完成原因、用量和耗时；应用重启后可恢复会话。
- [ ] 为长会话预留上下文裁剪或摘要字段，但本阶段不自动改写用户消息。

### 验收门槛

- [ ] 可完成至少十轮连续对话，文本逐步出现，停止后不再收到增量。
- [ ] 失败消息可重试，重新生成不会覆盖原回复，应用重启后历史仍可读取。
- [ ] 普通对话的出站请求不包含工作区路径、文件名、当前文档内容或其他未显式选择的数据。
- [ ] 输入法组合、长文本粘贴、代码块、取消请求和组件卸载均有自动化或可重复的手工验证步骤。

## M2：只读工作区 Agent

目标：用户明确选择 Agent 模式后，模型可以分步骤读取并理解工作区，但不能改变文件。

### 工具与编排

- [ ] 使用 AI SDK `ToolLoopAgent` 实现工具循环，并通过 `inputSchema` 校验入口输入。
- [ ] 第一批工具限制为 `list-workspace-files`、`read-workspace-file`、`search-workspace-text` 和 `read-current-document`。
- [ ] 主进程为每次运行注入工作区根目录；所有工具统一执行路径归一化、目录穿越和符号链接逃逸检查。
- [ ] 限制单文件大小、搜索结果条数、工具输出体积、总步骤数、总耗时和 token 用量；达到限制时返回结构化结果。
- [ ] 将运行时事件接入 `AgentRuntime`，统一表达推理文本、工具开始、工具完成、权限请求、完成、失败和取消。

### 界面与可见性

- [ ] 在提交前明确展示本次 Agent 可读取的工作区和数据范围。
- [ ] 消息中展示工具名称、状态、读取文件和失败原因；默认折叠冗长结果，不隐藏实际访问范围。
- [ ] 回答中的工作区结论附带可跳转的文件引用；引用至少包含相对路径和必要的行号或片段定位。
- [ ] Agent 模式与普通对话模式使用明确状态，不根据提示词自动提升权限。

### 验收门槛

- [ ] Agent 能通过多次工具调用回答跨文件问题，并为关键结论给出可验证的文件来源。
- [ ] `../`、绝对路径、工作区外符号链接、超大文件和超量搜索结果均被主进程拒绝。
- [ ] 只读运行时没有可达的写入、删除、重命名和 Shell 接口。
- [ ] 停止 Agent 后，正在执行的工具和后续步骤都能终止，并产生完整的结束事件。

## M3：可写工作区 Agent

目标：Agent 可以提出 Markdown 修改，但最终写入权仍属于用户和主进程。

### 修改提案与批准

- [ ] 增加 Markdown 创建和更新工具；工具输入包含相对路径、候选内容、修改理由和读取时的基准版本。
- [ ] 将写工具配置为需要人工批准；模型提出调用后暂停运行，主进程保存不可变的待审批输入。
- [ ] 复用编辑器的 Markdown 解析与 Diff 能力，展示目标路径、增删内容、基准版本和潜在冲突。
- [ ] 用户批准后，主进程重新校验工作区路径、权限和磁盘版本，再通过现有原子写入协议落盘。
- [ ] 用户拒绝时把拒绝结果返回工具循环；同一候选修改不得在没有新输入的情况下重复请求。
- [ ] 磁盘版本变化时禁止写入，保留候选内容并引导用户重新比较，不自动覆盖外部修改。

### 审计与状态同步

- [ ] 记录会话、模型、工具、目标路径、内容摘要、Diff、用户决策、结果和时间；不得记录供应商密钥。
- [ ] 写入完成后刷新工作区树、编辑器和文件索引；当前文档有未保存草稿时进入冲突流程。
- [ ] 为审批中的应用退出、窗口刷新、Agent 取消和会话恢复定义一致行为。
- [ ] 删除、重命名、批量改写、非 Markdown 文件和 Shell 保持不可用，直到有独立的权限与恢复设计。

### 验收门槛

- [ ] 「修改 README」只生成可审查 Diff；批准后文件原子更新，拒绝后磁盘内容不变。
- [ ] 审批期间发生外部修改时，写入被阻止且不会丢失用户版本或候选版本。
- [ ] 每次批准、拒绝、冲突和失败均可在会话与审计记录中追踪。
- [ ] 应用异常退出后不存在半写文件；恢复后不会自动执行未完成的批准请求。

## 横向任务

- [ ] 为模型调用、工具调用和 IPC 事件建立统一错误码，界面文案不暴露密钥或内部堆栈。
- [ ] 记录首 token 延迟、总耗时、token 用量、工具次数、取消率和失败原因；默认只保存本地。
- [ ] 建立回归样例：普通问答、中文长文写作、代码块、跨文件阅读、路径攻击、审批拒绝、版本冲突和恢复。
- [ ] 为写作质量建立人工评测集，分别评价事实保持、语气、结构、修改幅度和引用可靠性；不只比较单次演示效果。
- [ ] 当消息协议、权限模型或数据库事实源变化时，同步 `architecture.md`、相关目录 `.folder.md` 和源文件 `[DOC]`。

## 建议交付顺序

每项保持为可单独审查和回退的变更：

1. 供应商安全存储、配置 IPC 与默认模型解析。
2. 流式生成 IPC、取消和模拟供应商测试。
3. 对话界面、通用会话模型与历史恢复。
4. 只读 Agent 工具、路径安全和文件引用。
5. Diff 审批、版本复核、原子写入和审计。
6. 上下文控制、成本可见性、评测集和可靠性收尾。

M0 验收前不开始真实对话接入；M1 的流式协议稳定前不接工具事件；M2 的路径与资源限制通过测试前不开放写工具；M3 的 Diff、批准和冲突处理缺少任一项时，不允许 Agent 修改磁盘。
