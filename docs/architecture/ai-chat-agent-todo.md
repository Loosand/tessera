## 目标

从现有「新任务」界面出发，先交付四层安全基础，再收敛为统一创作运行时：

1. 安全、可持久化的供应商运行时。
2. 不读取工作区的普通 AI 对话。
3. 可读取工作区但不可修改文件的 Agent。
4. 通过 Diff、人工批准和审计记录修改 Markdown 的 Agent。
5. 不区分 Chat/Agent 的统一 `ToolLoopAgent`、每轮动态 Skill、动态资源和后端无关的项目/文档领域工具。

这个顺序是依赖关系，不是五套独立产品。当前独立任务与工作区任务都已使用 `ToolLoopAgent`，但仍按内部 mode
决定是否注入工作区工具，这是迁移期实现；
目标交互只保留一个自然对话入口，每轮运行自行决定直接回答或调用工具。内容存储仍处于探索阶段，暂以托管内容库
混合方案验证流程，同时保留数据库正文和完全开放外部工作区候选。详见
[统一创作 Agent 与内容存储探索](unified-creation-agent.md)。

## 固定边界

- 渲染层不持有供应商密钥，不直接请求模型，也不直接访问文件系统。
- 每轮默认只发送用户显式输入、显式附件和当前会话历史，不读取未附加的工作区、当前文档或剪贴板。
- 当前实际 Skill 通过 AI SDK instructions 注入，只改变执行方法；联网、资源读取与写入能力由本轮作用域、创作方式和请求期模型端点共同解析，Skill 声明本身不授予权限。
- 当前文件适配器的工作区根目录由主进程注入，模型不得通过参数自行选择或扩大目录；未来数据库适配器也必须使用稳定资源 ID 和相同授权语义。
- 只读 Agent 不暴露写入、删除、重命名、Shell 或任意网络接口；仅创作方式启用且当前模型端点已验证时，可获得供应商原生联网工具。
- 可写 Agent 第一版只创建或更新 Markdown，不删除或重命名文件。
- 任何 Agent 写入都必须先展示 Diff；批准前不改变磁盘，拒绝后不得继续尝试同一写入。
- 每次工具调用设置路径、结果大小、步骤数、时间和 token 上限。
- 探索阶段继续以 Markdown 为事实源，数据库只保存会话、索引、运行状态和审计；最终存储评审前不得引入正文双写或不可逆迁移。

## 目标数据流

```text
用户输入与本轮创作提示
  -> 渲染层消息界面
  -> 类型化 IPC
  -> 主进程解析 RunPolicy、供应商、模型、Skill、资源和工具
  -> AI SDK ToolLoopAgent（迁移期仍按内部 mode 装配两套工具定义）
  -> 文本增量或工具事件
  -> 渲染层呈现

可写 Agent 的文件提案
  -> 主进程冻结路径、基准版本和候选内容
  -> 渲染层展示 Diff
  -> 用户批准或拒绝
  -> 主进程重新校验磁盘版本
  -> 原子写入或报告冲突
  -> 记录审计事件
```

## M1：普通 AI 对话

目标：把「新任务」从本地输入界面接成可停止、可恢复的多轮流式对话，同时保持良好的手动输入和编辑体验。

### 流式协议

- [ ] 在 `packages/contracts` 定义开始、文本增量、完成、失败和取消事件，包含稳定的会话 ID、消息 ID、请求 ID 和递增序号。
- [ ] 在主进程使用 AI SDK `streamText` 发起生成，并用 `AbortController` 实现停止生成和窗口关闭清理。
- [x] 为 React `useChat` 实现 Electron `ChatTransport`；渲染层不使用会直接请求外网的 transport。
- [ ] 处理重复事件、乱序事件、订阅释放、渲染进程刷新和中途取消，避免消息重复或请求悬挂。
- [x] 使用合成 `start → text-start → text-delta → text-end → finish` 序列验证 AI SDK React 消费者逐段收到正文，结束后 Part 进入完成状态。
- [x] 透传供应商明确返回的 `reasoning-start → reasoning-delta → reasoning-end`，按原始 Part 顺序用可折叠、紧凑 Markdown 过程块展示，不合成伪思维链。

### 会话与界面

- [ ] 提交首条消息后，将居中的任务输入框平滑转换为消息列表和底部固定输入框。
- [ ] 支持多行输入、选区编辑、撤销、粘贴、中文输入法、键盘发送与鼠标发送；流式生成期间仍允许整理下一条输入。
- [ ] 为 Markdown、代码块和链接补齐复制与完整交互；正文和 reasoning 已共享基础 GFM 渲染，停止、重试和重新生成已具备首版。
- [x] 将 reasoning、正文、来源和工具调用拆为独立 Part 呈现；reasoning 默认展开、可折叠并以紧凑密度复用正文 Markdown 渲染器，正文使用 SDK Part 状态显示增量光标，工具状态不混入 Markdown。
- [x] 消息滚动只在用户贴底时自动跟随；离开底部后保留阅读位置并显示返回最新消息按钮。
- [ ] 明确显示当前供应商与模型；切换模型只影响下一次生成，并记录到对应消息。
- [x] 确定通用任务会话模型：普通对话允许没有工作区，Agent 会话必须绑定工作区；通过前向迁移落地，不重写已有迁移。
- [x] 持久化消息内容、reasoning/来源/工具等消息 Part 以及供应商和模型；应用重启后可恢复会话。
- [x] 使用无服务端副作用的 `request-user-input` 客户端工具只处理核心语义歧义，单次只问一个问题、每个用户请求最多询问一次；持久化等待态，并在回答、跳过或关闭后通过类型化工具输出自动续跑。
- [x] 研究 Skill 在多步任务前通过 `publish-research-plan` 发布结构化目标、范围、交付物和问题列表，使用专用组件呈现且不扩大工具权限。
- [ ] 持久化每轮完成原因、token 用量和耗时。
- [ ] 为长会话预留上下文裁剪或摘要字段，但本阶段不自动改写用户消息。

### 验收门槛

- [ ] 可完成至少十轮连续对话，文本逐步出现，停止后不再收到增量。
- [ ] 失败消息可重试，重新生成不会覆盖原回复，应用重启后历史仍可读取。
- [ ] 普通对话的出站请求不包含工作区路径、文件名、当前文档内容或其他未显式选择的数据。

## M2：只读工作区 Agent

目标：用户进入工作区任务或打开文档侧栏后，系统在内部使用 Agent，使模型可以分步骤读取并理解工作区，但不能自行改变文件。

### 工具与编排

- [x] 使用 AI SDK `ToolLoopAgent` 实现工具循环，并通过 `inputSchema` 校验入口输入。
- [x] 第一批工具限制为 `list-workspace-files`、`read-workspace-file`、`search-workspace-text` 和 `read-current-document`。
- [x] 主进程为每次运行注入工作区根目录；所有工具统一执行路径归一化、目录穿越和符号链接逃逸检查。
- [x] 限制单文件大小、搜索结果条数、工具输出体积、总步骤数、总耗时和 token 用量；达到限制时返回结构化结果。
- [x] 将 AI SDK 工具增量通过泛型 `AgentRuntime` 端口输出，保留推理、工具、审批、完成、失败和取消的 `UIMessageChunk` 语义。

### 界面与可见性

- [x] 在提交前明确展示本次 Agent 可读取的工作区和数据范围。
- [x] 消息中展示工具名称、状态、读取文件和失败原因；冗长结果不展开到消息正文，但实际访问的相对路径保持可见。
- [x] 回答中的工作区结论支持相对 Markdown 链接跳转到文件与源码行号。
- [x] Agent 与普通对话使用任务级明确的内部状态，不根据提示词自动提升权限；界面不暴露运行时选择，缺少工作区或工具能力时阻止发送而不降级。

### 验收门槛

- [ ] Agent 能通过多次工具调用回答跨文件问题，并为关键结论给出可验证的文件来源。
- [x] `../`、绝对路径、工作区外符号链接、超大文件和超量搜索结果均被主进程拒绝或截断为结构化受限结果。
- [x] 只读运行时没有可达的写入、删除、重命名、Shell 和任意网络接口；供应商原生联网仅由创作方式和已验证端点显式注入。
- [ ] 停止 Agent 后，正在执行的工具和后续步骤都能终止，并产生完整的结束事件。

## M4：统一创作 Agent 与存储探索

目标：在不改变安全边界的前提下消除任务级 Chat/Agent 分叉，让同一会话自然完成问答、研究、写作、创建产物和整理项目；用后端无关的领域工具评估最终存储方案。

### 统一运行与每轮策略

- [x] 在编码前针对锁定的 AI SDK 版本完成能力矩阵，至少核对 `ToolLoopAgent`、call options / `prepareCall`、`prepareStep`、`stopWhen`、`toolApproval`、typed UI messages、ChatTransport、生命周期和子 Agent；能力矩阵记录在[统一创作 Agent 与内容存储探索](unified-creation-agent.md)，依据 `ai@7.0.73` 随包 docs/source。
- [x] 让无工作区任务也通过 AI SDK `ToolLoopAgent` 运行；无资源且无需搜索时允许零工具直接生成文本。
- [ ] 定义 `RunPolicy`，根据本轮创作提示、用户 turn、显式资源、模型能力和权限解析实际 Skill、联网、工具、审批和资源限额；优先通过 `callOptionsSchema` / `prepareCall` 配置同一 Agent，不复制多套 Agent 类。
- [ ] 把实际 Skill、能力策略和资源快照固化到 `task_runs`；当前已通过 `0009-task-run-policy` 保存 mode、Skill、思考和联网，工具/资源快照仍待实现；保留旧 `task_sessions.mode` / `skill_id` / `workspace_id` 的兼容读取。
- [x] 允许自动/研究/写作/问答在每轮发送前切换；同一任务可以从普通问答进入研究和写作，旧 run 不被回写。
- [ ] 使用 `prepareStep` / `activeTools` 处理 step 内收窄和 `stopWhen` 处理循环停止；任何 step 只能缩小 RunPolicy 授权，不能临时扩大资源或工具。
- [ ] 通过 AI SDK `toolApproval` 表达敏感工具暂停，并用 `prepareCall` 绑定本轮权限策略；Tessera 只持久化审批、Diff 和审计，不自建平行工具状态机。

- [ ] 使用 AI SDK 生命周期回调记录 step、工具耗时、usage 和 finish reason，再关联现有 `task_run_events`，避免从 UI chunk 反推观测数据。
- [ ] 使用同一薄 `AgentRuntime`、消息 Part、暂停/续跑、审批、取消和运行恢复协议，停止为 Chat 和 Agent 维护两条产品链路。
- [ ] Electron transport 只实现标准 `ChatTransport` 的 IPC/重连差异；由于 `DirectChatTransport` 当前不支持 reconnect，只用于适合的测试，不另写 React chat 状态机。

- [ ] 文档创建后在同一 TaskPage 打开 Artifact 协作视图；项目创建和移动完成后更新资源关联，不复制任务历史。
- [ ] 创建、移动、重命名执行冲突预检、授权、活动展示、审计和恢复信息；覆盖、删除、Shell 与任意 MCP 继续保持独立高风险边界。

### 存储评审

- [ ] 用同一组端到端场景分别评估数据库正文、托管内容库混合方案和完全开放外部工作区，不让 UI 与工具协议绑定实验后端。
- [ ] 记录首次设置成本、任务成功率、操作失败率、外部编辑冲突、导入导出、备份恢复、多端需求和迁移成本。
- [ ] 在任何正文事实源迁移前形成独立 ADR，明确权威副本、事务/恢复、备份、导出和旧数据迁移；评审前禁止数据库/Markdown 双写。

### 验收门槛

- [ ] 同一任务完成“普通问答 → 联网研究 → 写作 Skill → 创建文档 → 建立项目 → 移动文档”，全程没有 Chat/Agent 选择。
- [ ] 每个 run 可以恢复并解释实际模型、Skill、资源和工具；切换创作方式不改变旧消息的权限语义。
- [ ] 当前混合实验退出 Tessera 后仍能直接打开全部 Markdown；删除 SQLite 索引不会删除或覆盖正文。
- [ ] 最终存储评审可以替换适配器而不改写核心对话、领域工具和活动 UI 契约。

## 横向任务

- [ ] 为模型调用、工具调用和 IPC 事件建立统一错误码，界面文案不暴露密钥或内部堆栈。
- [ ] 记录首 token 延迟、总耗时、token 用量、工具次数、取消率和失败原因；默认只保存本地。
- [x] 为路径攻击、审批批准/拒绝、版本冲突、完整工具历史和运行事件持久化建立自动化回归；普通问答与写作质量评测仍需扩充。
- [ ] 为写作质量建立人工评测集，分别评价事实保持、语气、结构、修改幅度和引用可靠性；不只比较单次演示效果。
- [ ] 当消息协议、权限模型或数据库事实源变化时，同步 `architecture.md`、相关目录 `.folder.md` 和源文件 `[DOC]`。

## 建议交付顺序

每项保持为可单独审查和回退的变更：

1. 供应商安全存储、配置 IPC 与默认模型解析。
2. 流式生成 IPC、取消和模拟供应商测试。
3. 对话界面、通用会话模型与历史恢复。
4. 只读 Agent 工具、路径安全和文件引用。
5. Diff 审批、版本复核、原子写入和审计。
6. 统一 `ToolLoopAgent` 与每轮 RunPolicy，保留旧任务兼容。
7. 动态资源、Artifact 和后端无关的项目/文档领域工具。
8. 托管内容库混合实验与三种存储方案评审。
9. 上下文控制、成本可见性、评测集和可靠性收尾。

M0 验收前不开始真实对话接入；M1 的流式协议稳定前不接工具事件；M2 的路径与资源限制通过测试前不开放写工具；M3 的 Diff、批准和冲突处理缺少任一项时，不允许 Agent 修改磁盘；M4 存储评审完成前不迁移正文事实源或建立双写。
