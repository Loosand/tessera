# 分形文档规范

> 代码源头：`AGENTS.md`、`.agnets/skills/fractal-document/SKILL.md`
>
> 状态：已实现。

## 目标

让架构知识同时存在于仓库规则、目录地图、源文件契约和跨目录深文档中。读者可以从任意文件逐层
找到上下文，不依赖一份容易失真的总览文档。

## 四层文档

1. `AGENTS.md` 定义全仓库协作规则。
2. `.folder.md` 描述目录的局部职责和直接成员。
3. 源文件 Header 描述单个文件的输入、输出、位置与文档依赖。
4. `docs/architecture/` 解释跨目录的数据流、安全边界和关键决策。

上层不复制下层细节。目录地图只列直接成员，深文档不维护会快速失效的完整文件树。

## 修改流程

1. 修改前读取根 `AGENTS.md`、最近的 `.folder.md` 和 Header 指向的文档。
2. 文件契约变化时更新 Header。
3. 文件增删、重命名或职责变化时更新最近的 `.folder.md`。
4. 跨目录行为变化时更新对应架构文档。
5. 用「已实现」「部分实现」「规划」区分事实与意图。
6. 执行格式、lint、类型、测试与构建检查。

## Header 模板

```ts
/**
 * [INPUT]: 本文件依赖的外部输入与契约
 * [OUTPUT]: 本文件向外提供的能力
 * [POS]: 本文件在所属模块中的位置
 * [DOC]: 与行为同步的设计或架构文档
 *
 * [PROTOCOL]:
 * 1. 文件契约变化时更新本 Header。
 * 2. 成员或职责变化时同步最近的 .folder.md。
 * 3. 行为变化时同步 [DOC] 指向的文档。
 */
```

配置文件、纯样式文件、类型声明和生成文件可以免除 Header；一旦包含非显然的行为规则，仍应添加
中文说明。

## `.folder.md` 模板

```markdown
# 目录名

## 地位
## 逻辑
## 约束
## 成员清单
## 触发器
```

触发器至少覆盖成员增删、重命名和职责变化。检查文档时以实际代码和配置为准，不能仅凭计划描述
推断功能已经实现。
