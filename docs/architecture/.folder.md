# docs/architecture

## 地位

记录需要跨越应用和共享包维护的工程机制。

## 逻辑

每份文档链接代码源头，说明数据事实源、运行时边界、已实现协议和后续决策条件。

## 约束

- 文档开头标明代码源头和能力状态。
- 使用「已实现」「部分实现」「规划」区分事实与意图。
- 行为变化时由源文件 Header 的 `[DOC]` 链接触发同步。
- 外部调研只保留影响当前决策的结论，不在本目录长期保存产品对比记录。

## 成员清单

- `ai-chat-agent-todo.md`：供应商运行时、普通对话、只读 Agent 与可写 Agent 的实施顺序和验收门槛。
- `ai-providers.md`：供应商协议适配器、具名连接、可选模型目录、AI SDK 适配与页面级流式恢复边界。
- `task-navigation.md`：通用 Chat/Agent 任务会话、mode、工作区绑定、历史/后台运行恢复与导航顺序。
- `skill-system.md`：标准 `SKILL.md`、内置注册表、渐进式模型加载、任务选择与权限边界。
- `database.md`：SQLite 数据边界、连接生命周期和迁移机制。
- `editor.md`：Typeset 主题、TipTap/CodeMirror 编辑表面、Markdown 往返、性能基准、草稿同步和 Agent 修改边界。
- `local-version-history-and-git-workspaces.md`：本地文档版本历史、已有 Git 工作区轻量管理及两套版本语义的协作边界。
- `plugin-system.md`：插件包、贡献点、隔离运行时、能力权限、安装更新和社区目录的架构边界。

## 触发器

新增或删除架构文档、事实源、状态约定或跨目录协议时更新本文。
