## 地位

研究不是“打开联网并让模型多想一会儿”的回答预设，而是一套由运行时保证的工作流。Skill 负责研究方法、
来源判断和写作规范；统一 Agent Runtime 负责阶段、工具可达性、来源状态、安全护栏、恢复和完成门槛。两者必须配合，
但不能让 Prompt 代替协议。

本文是主动研究流程的架构事实源。供应商差异继续由
[AI 供应商与模型发现](ai-providers.md)处理，任务恢复由[任务会话与导航](task-navigation.md)处理，Skill 的发现、
注入和权限边界继续由[Skill 系统](skill-system.md)处理。

## 决策

1. 用户显式选择“研究”时，运行标准研究流程；即使问题看起来简单，也先发布一份紧凑计划。原子事实查询应由
   “自动”或“问答”直接回答，不把显式研究降级成一次搜索。
2. 搜索、阅读、引用、推荐和保存是不同动作，界面和数据层不得用一个“来源数”混合表达。
3. 搜索结果中的标题、URL、摘要、供应商上下文或加密续轮内容只证明“发现过来源”，不自动证明 Tessera 已读取
   页面正文。只有获得可核查正文或结构化页面内容，并记录读取结果后，来源才进入“已阅读”。
4. 研究进度来自运行时事件和持久化状态，不从模型的自然语言旁白推断。模型不能仅通过说“我已经阅读”推进阶段。
5. 继续使用 AI SDK `ToolLoopAgent`、标准 Tool Part 和生命周期回调，不平行实现第二套 Agent 循环、工具状态机或
   消息协议。Tessera 只增加研究领域状态和完成条件。
6. 公开网页优先使用低成本静态读取；JavaScript 页面、所选网络路径下静态读取失败或普通提取只得到壳页时，回退到
   同一网络模式、无登录态的隐藏沙箱浏览器。默认跟随系统代理，用户可显式改为直连；不能在任务中途静默换路。
   浏览器动画或快照不是研究质量的前提，正文与证据记录才是。

## 搜索不等于阅读

“支持 Web Search”不能推导出模型已经看到每个结果页面的完整内容。实际可见范围取决于供应商协议，可能只是
搜索摘要，也可能包含供应商提取的片段，个别协议还会发出 `openPage` / `findInPage` 动作。Tessera 不根据产品
动画、页面快照或模型措辞猜测能力，而根据可审计工具结果判定：

| 动作 | 最低可审计结果 | 当前状态 | 可用于什么 |
| --- | --- | --- | --- |
| 搜索 / Discover | 查询、结果 URL、标题及供应商返回的摘要或片段 | 已实现（消息级），结构化来源池规划 | 建立候选来源池、设计下一轮查询 |
| 阅读 / Read | 规范化 URL、获取时间、正文或结构化内容、内容哈希、可定位片段 | 已实现（公开 HTML/纯文本） | 理解来源主张、提取证据、判断上下文 |
| 引用 / Cite | 具体声明到已阅读来源片段的关系 | 已实现（证据账本） | 支撑报告中的事实与来源观点 |
| 推荐 / Recommend | 通过质量和相关性筛选、值得用户保留的来源集合 | 已实现（证据链来源） | 让用户复核并选择长期材料 |
| 保存 / Save | 用户确认后写入项目的来源快照、笔记或元数据 | 已实现（必要片段与定位） | 后续阅读、写作和重复研究 |

供应商返回明确的页面读取结果时，适配层可以把它归一化为“已阅读”事件；只有 URL、搜索摘要或不透明的
`encrypted_content` 时仍算“已发现”。正文获取失败、受登录限制或只读到错误页时必须记录失败原因，不能继续
作为已阅读来源引用。

## 当前实现与剩余边界

当前研究链路已经具备以下闭环：

- `RunPolicy` 为研究选择高推理强度和供应商已验证的原生搜索；研究不设置应用侧累计 Token 预算。已知模型必须显式
  透传档案声明的原生最大输出，避免兼容 SDK 把未知模型静默压到 4096；未知上限才交给供应商默认。运行时只保留
  防死循环保险丝：未知/较小上下文为 32 步，128k 以上为 48 步，500k 以上为 64 步，总时长 30 分钟；保险丝不是
  完成质量门槛。
- 研究 Skill 要求模型拆解问题、深读、登记证据、区分事实/推断/不确定性并执行完成检查。
- `prepareStep` 根据持久化进度收窄 `activeTools`：计划发布前只有核心消歧和 `publish-research-plan` 可达；计划后
  禁止直接输出最终文本；首次深读后若证据账本仍为空，下一步优先登记证据，同时保留重新深读当前运行缺失正文的
  来源以及在材料确实不足时部分完成的逃生路径；接近循环保险丝时只开放完成检查。完成检查通过后固定保留一个
  无工具最终答复步骤。在此之前的模型进度旁白不作为报告展示，完成检查通过但没有生成报告时整轮标记失败。
- 供应商搜索 Tool Part、查询、URL 来源和运行指标可以进入消息与任务运行记录；renderer 能兼容部分供应商的
  `search`、`openPage` 和 `findInPage` 动作。
- 主进程 Reader 在主页面、重定向和浏览器子资源请求前复核公网地址，限制协议、凭据、响应类型、大小、超时和
  正文长度。桌面生产路径为 `system` / `direct` 分配隔离的 Electron Session；默认 `system` 继承操作系统代理，
  用户可在 AI 设置中改为 `direct`。每次研究启动时冻结选择并写入 `task_runs.resource_summary_json`，设置变更只影响
  后续运行；静态读取失败时才创建同分区、隐藏、沙箱化、无 Node 权限、无窗口打开和无下载能力的 BrowserWindow。
  正文相关性、登录墙、验证页和 JS 空壳还要经过语义前置校验。
- `record-research-evidence` 只接受已读来源和逐字存在于当前正文的片段；`finalize-research` 校验逐问题覆盖、证据、
  读取状态和交叉来源。资料不可访问、相互冲突或合理尝试后仍不足时可带限制部分完成，不与抽象 Token 额度绑定。
- 完成门槛满足后仍必须调用 `recommend-research-sources`，推荐至少一个已经进入证据链的已读来源；推荐只建立控制
  关系，不自动写文件。用户在进度卡中明确选择后，才把必要证据片段、定位与链接写入内容库 Markdown Artifact。
- 研究笔记由持久化计划、问题、已读来源、证据、推荐与限制按需重建，研究进行中即可预览；后续选择“写作”时，
  当前任务最近一次已完成研究以受限 `<research-handoff>` 注入，不重新搜索或猜测已核验事实。
- 研究消息重新生成会创建新的 request，而不是修改旧运行。Transport 提交目标助手消息，主进程从其持久化
`requestId` 解析 `resumedResearchRequestId`，把计划、问题覆盖、来源元数据、证据、推荐与结果克隆到新 run，并把
  provenance 写入资源摘要。续跑上下文携带当前稳定来源 ID；网页全文仍不入库，已有证据支撑的来源保留已读状态，
  没有持久化证据的临时已读来源重置为待读取，若要从继承来源提取新片段必须重新阅读。
- 供应商在搜索/读取工具完成后、最终正文生成前失败时，Transport 会在 AI SDK 删除失败助手消息之前提取所有非
  preliminary 的 `output-available` Tool Part；新 request 把这些 Part 作为已完成历史补回，并以
  `continuedFromMessageId` 写入运行资源摘要。模型从工具结果之后继续综合，不重复同一搜索或读取；这条请求级续跑与
  研究领域 provenance 可以叠加，但不会重放写入、审批或未完成工具。
- 工作区工具按当前请求相关性开放，而不是因任务碰巧绑定工作区就自动开放。显式当前文档、Markdown 附件、对工作区/
  本地文件的明确请求，或确实承接上一轮工作区工具结果时才组合 Markdown 读写工具；纯公开网页研究不会再“顺便看看
  工作区有没有记录”。
- `research_runs`、`research_questions`、`research_sources`、`research_evidence` 与
  `research_source_recommendations` 保存领域控制状态；消息中的研究进度卡只聚合真实 Tool Part 输入输出，不读取模型旁白。
- 主进程直接收口 task session 的运行、等待输入、完成、取消与失败状态；`research-run-audit` 再核对事件连续性、
  计划顺序或续跑 provenance、工具/数据库计数、完成检查和最终报告，用于真实供应商黄金运行回归。模型的逐 token
  正文、推理和工具参数增量在持久化与 IPC 前按 ID/类型顺序安全合并，非增量事件和结束前强制刷新，避免事件数量
  反过来拖垮恢复与界面。若运行已经完成但助手消息尚未落盘，终态事件仍可恢复一次；助手消息关联该 request 后即
  停止重放。优化前的高密度历史只在恢复快照中合并，不改写原始审计序列。
- 完成态研究再次生成时，审计沿 provenance 继承祖先已经执行的计划、检索、证据、推荐和完成检查，但最终正文只
  统计当前 run；因此续跑无需重复工具副作用，也不能以祖先报告代替本轮交付。

2026-08-23 的真实校准任务先后暴露了三组边界。第一组是显式研究 FKJ 只完成两次 Web Search，没有计划或
可审计阅读，却直接生成完整人物介绍；由此建立了计划门禁、搜索/阅读分层和证据完成检查。第二组已经进入多步循环，
但应用侧固定 8 步、累计 80k Token、每步 4k 输出把 1M 上下文模型提前逼入收尾；Node 直连 Reader 又绕过 macOS
代理，导致 Wikipedia 超时，Apple Music 通用播放器壳页反而被误判为已读，最终运行结束时没有报告。当前实现据此
移除了研究累计额度和 Tessera 自造的单步额度，改为显式透传模型原生最大输出，并使用上下文感知保险丝、可选系统
代理/直连的 Electron Session + 沙箱浏览器回退、正文相关性校验、错误码和“无最终报告即失败”不变量。第三组真实
续跑完成了 3 次搜索、2 个已读来源、2 个不可用来源、15 条证据、2 个推荐和 5/5 问题覆盖，但 15,552 条逐 token
事件让 renderer 在数据库完成后仍长时间追赶，甚至出现运行已经完成而助手消息尚未保存的短暂断层；据此加入了
增量事件合并、终态事件账本恢复和真正的研究状态续跑。完整基线见
`docs/quality/research-fkj-golden-run.md`。校准样本只用于验证 Tessera 自身行为，不作为长期保存的竞品比较。

## 目标状态机

一次显式研究运行使用以下领域阶段：

```text
preparing
  -> planning
  -> discovering
  -> reading
  -> verifying
  -> synthesizing
     -> recommend evidence-linked sources
     -> finalize coverage
  -> completed

任一执行阶段
  -> waiting_for_user | blocked | cancelled | failed

```

| 阶段 | 运行时要求 | 允许的主要动作 | 退出条件 |
| --- | --- | --- | --- |
| `preparing` | 解析题目、显式材料、权限、端点能力和安全护栏 | 必要时请求一次核心消歧 | 研究边界可执行 |
| `planning` | 创建并发布目标、范围、交付物和研究问题 | `publish-research-plan` | 计划通过 Schema，问题有稳定 ID |
| `discovering` | 为每个问题形成候选来源池并去重 | Web Search、工作区搜索 | 候选来源覆盖关键问题或记录缺口 |
| `reading` | 从候选池选择高价值来源并读取正文 | `read-web-source`、工作区读取 | 关键来源有读取结果或明确失败 |
| `verifying` | 交叉核对声明、冲突、时间和来源质量 | 补充搜索/阅读、记录证据 | 核心声明有支持、反例或不确定性 |
| `synthesizing` | 检查覆盖、推荐证据链来源并冻结结果 | `recommend-research-sources`、`finalize-research` | 推荐已形成且完成门槛通过 |
| `completed` | 只使用已冻结证据交付最终报告 | 无工具最终文本 | 报告实际生成且引用关系可校验 |

阶段约束不要求为每一步单独发起新的模型请求，也不要求用户持续盯着动画。当前实现用 `prepareCall` 冻结本轮
总策略，用锁定 AI SDK 版本的 `prepareStep` / `activeTools` / `toolChoice` 收窄逐步动作；领域状态由主进程应用服务
维护，工具执行和消息 Part 状态仍由 AI SDK 管理。`waiting_for_user`、取消和失败继续沿用任务/工具生命周期，不复制
到研究 phase 枚举。

## 来源与证据模型（已实现 P0）

第一版不建设通用知识图谱，只保存完成研究闭环所需的最小关系：

```text
ResearchRun
  -> resumedFrom ResearchRun（可选 provenance；新 request）
  -> ResearchQuestion
  -> ResearchSource
    -> ResearchEvidence
    -> ResearchSourceRecommendation
```

### `ResearchPlan`

- 以 `requestId` 绑定稳定研究运行，保存目标、范围、排除项语义和交付物；
- 最多八个研究问题，每个问题有稳定 ID、状态与覆盖说明；
- P0 计划版本固定为 1，同一运行不能静默替换；可见修订留给后续版本。
- 续跑不重新发布相同计划；新 run 从显式祖先复制计划和问题状态，审计沿 provenance 验证计划先于整条链的首次发现。

### `ResearchSource`

- P0 保存原始 URL、规范化 URL、最终 URL、标题、作者、发布时间和发现/读取时间；站点可由 URL 推导；
- 发现它的查询和对应研究问题；
- `discovered`、`shortlisted`、`reading`、`read` 或 `unusable` 状态及失败原因；
- P1 再结构化来源类型和上下文相关的质量判断，不用单一全局分数替代判断理由。

“已引用”“已推荐”“已保存”不是互斥的读取状态，而是来源与声明、推荐集、工作区材料之间的关系。

### 读取字段与 `ResearchEvidence`

- `ResearchSource` 同时保存最终 URL、获取时间、内容类型、字符数、截断信息、内容哈希和失败原因；
- 可定位正文片段、章节/段落/时间戳、片段摘要和语言；
- 证据支持的研究问题、声明类型、支持/反驳/限定关系；
- 对无法获取原文、动态变化或只有二手转述的内容明确降级。

网页原文的长期保存必须遵守版权、服务条款、用户权限和存储策略。第一版可以只持久化必要片段、摘要、定位信息和
内容哈希；是否保存完整快照由后续采集设计决定，不能因为技术上可抓取就默认长期复制。

## 工具边界

| 工具或能力 | 状态 | 职责 |
| --- | --- | --- |
| `publish-research-plan` | 已实现 P0 | 展示并持久化结构化计划；运行时保证首次搜索前调用 |
| 供应商 `web_search` | 已实现 | 发现候选来源，保留查询和来源 Part |
| `read-web-source` | 已实现 P0 | 获取并解析公开 HTML/纯文本，返回可审计正文、定位和失败原因 |
| `record-research-evidence` | 已实现 P0 | 把当前运行已读取的逐字片段关联到研究问题和待支持声明 |
| `finalize-research` | 已实现 P0 | 执行领域完成检查，冻结覆盖、来源、结果和限制汇总 |
| `recommend-research-sources` | 已实现 P1 | 只从证据链已读来源中形成带理由的推荐，不代表用户保存 |
| 研究笔记读取与来源保存 IPC | 已实现 P1 | 增量预览可恢复笔记；用户选择后创建必要片段材料 Artifact |
| 研究到写作交接 | 已实现 P1 | 把最近完成研究作为受限材料注入写作 Skill，不重新猜测事实 |
| 隔离浏览器读取后备 | 已实现 | 处理 JavaScript 渲染和静态读取失败；不复用用户登录态，不承诺绕过登录墙 |

`read-web-source` 是窄网络工具，不是任意 URL 请求器。主进程必须限制协议、重定向、地址范围、响应类型、下载大小、
超时和解析成本，拒绝本机、内网、云元数据地址与非预期二进制，防止 SSRF 和提示注入扩大权限。网页内容始终是
不受信任材料，其中的指令不得改变系统、Skill、工具或授权。

## 研究完成门槛（已实现 P0）

`finishReason = stop` 或模型输出一篇长文不代表研究完成。显式研究至少需要通过以下领域检查：

1. 已发布有效计划，所有研究问题标记为已覆盖、部分覆盖或未覆盖；
2. 关键事实只由已阅读证据支持，不把搜索摘要和模型记忆伪装成页面引用；
3. 适合一手来源的问题优先找到一手来源；找不到时解释搜索范围和退而使用的来源；
4. 重要声明至少经过独立来源交叉核对，或明确标记单一来源、冲突和不确定性；
5. 交付物中的引用能回到来源和证据位置，来源失败、正文截断和时间敏感性可见；
6. 结尾提供覆盖说明、主要遗漏和下一步，而不是以达到工具额度冒充完成。

不同题目最终不应使用僵硬的统一来源数量。P0 在尚未引入研究类型策略前采用保守基线：完整完成至少需要两个已读
来源参与证据交叉核验，每个标记为已覆盖的问题至少有一条证据；这不是“搜索十次”式的表演指标。后续可按研究
类型调整基线，但必须保留可解释门槛与失败状态。部分完成由实际材料限制触发：至少尝试读取一个来源，并逐题保留
未覆盖状态、失败原因和限制；不能仅因运行接近保险丝就显示为完整研究，也不能把保险丝描述成研究预算。

## 进度与工作文档

任务界面显示的进度由领域事件驱动，至少区分：

- 计划中的研究问题及覆盖状态；
- 已搜索查询数、已发现来源数、已阅读来源数、已引用来源数；
- 当前正在读取的来源及失败原因；
- 已完成阶段、剩余阶段和部分完成原因；
- 最终推荐来源，以及用户是否选择保存。

“找到了 59 个来源”不能和“阅读了 7 个来源”合并显示。页面快照、浏览器画中画和播放式轨迹可以改善用户理解，
但只是事件的视图，不是 Agent 深度的证据。

计划、来源、证据、推荐与保存关系都绑定任务运行持久化。消息内按标准 Tool Part 呈现已读/不可用来源、证据数量、
问题覆盖、推荐和完整/部分结果；从首次成功读取开始即可按需重建并预览研究工作笔记，不等待最终报告，也不维护第二
份可漂移正文。当前笔记是只读派生视图，用户选择保存推荐来源时才创建正式 Markdown Artifact；将整个笔记转为可编辑
独立 Artifact 仍需明确版本和审批语义，不能在用户正文中无审批地持续改写。

失败后重新生成不是从空白 Prompt 重做：新 run 复制可审计控制状态并继承证据，旧 run 保持不可变；`reading` 以及
没有持久化证据支撑的 `read` 状态会重置为 `discovered`。因为网页正文没有长期保存，继承证据仍可用于综合，但新增
声明或摘录必须再次调用 Reader。
这种续跑解决“预算已耗尽、网络中断或工具 JSON 截断后从头研究”的浪费，同时没有承诺通用的任意步骤 durable replay。
若失败发生在工具已经返回之后，重试还会复用消息中可公开持久化的 Tool Part；供应商原生工具的
`providerExecuted` 标记随消息保存，避免把服务端搜索误还原成需要本地重新执行的工具。嵌套 RetryError 在进入公开
字符串前提取稳定类别与可安全公开的 HTTP 状态，原始响应体、Header 和凭据仍不进入消息。

## 网页读取层级

按成本和权限从低到高选择读取方式：

1. **供应商页面读取**：协议明确返回正文、片段和页面动作时，归一化为可审计读取事件；
2. **受限 Reader**：Electron Session 按本轮冻结的 `system` / `direct` 模式抓取公开 HTML，提取正文、元数据和定位；
   `system` 是默认值并读取操作系统代理，`direct` 明确绕过系统代理；
3. **隔离浏览器**：Reader 超时、只得到无关壳页或需要 JavaScript 渲染时，使用同一 Session 分区和网络模式的隐藏
   沙箱窗口，不把“浏览器回退”误解成切换网络出口；
4. **用户会话浏览器**：只有任务确实依赖用户已登录状态且用户明确授权时才考虑，不能默认读取现有浏览历史、Cookie
   或其他标签页。

浏览器可见快照只能证明某一时刻渲染了页面。研究记录仍要保存 URL、获取时间、内容结果、定位和失败状态，不能把
视频式回放当作证据账本。

P0 不提供手填代理 URL：系统代理由操作系统统一配置，Tessera 只保存非敏感的模式选择。应用也不会在直连超时后
自动改用系统代理，否则同一运行的网络边界将不可解释。自定义代理、按站点规则和连通性诊断需要独立安全设计。

3. **已实现**：受限 `read-web-source` 让来源从“已发现”显式进入“已阅读”或“不可用”；
4. **已实现**：证据记录和 `finalize-research` 完成检查阻止缺少计划/读取/覆盖汇总的完整完成态；
5. **已实现**：用真实工具事件呈现数量和读取失败原因，工具协议错误不伪装成网页来源；SQLite 保存停止、失败和
   重启后的领域进度，材料确实不足时可诚实标记部分完成；

## 验收场景

1. 用户显式研究 FKJ：先看到研究问题，再看到多轮搜索、被选择阅读的来源、失败来源和证据覆盖；最终介绍中的
   生平、作品、现场特征和最新动态都能回到已阅读材料。
2. 用户在自动方式问“FKJ 的全名是什么”：允许零计划或一次搜索直接回答，不伪装成深度研究。
3. 搜索结果包含聚合站、商店和未来日期噪声：系统不因结果数量多而完成，优先读取官方/一手材料并解释排除项。
4. 页面只有搜索摘要、登录墙或抓取错误：来源保持“已发现”或“不可用”，不能进入已引用计数。
5. 多个关键页面确实不可访问：在实际读取尝试后交付已核实内容、未覆盖问题和限制，任务状态为部分完成；若只是
   接近循环保险丝，则先执行完成检查，不能把技术护栏伪装成材料结论。
6. 用户重启应用：研究计划、来源读取状态、证据关系和当前阶段可以恢复，不重复声称已经读过未完成页面。
7. 用户在 AI 设置把研究网络从系统代理改为直连：当前运行继续使用启动时的系统代理分区，下一次研究的资源摘要
   记录 `direct`，静态 Reader 与浏览器回退都保持直连；反向切换同理。
8. 用户查看进行中的研究：从持久化领域状态重建笔记；研究完成后看到推荐来源，只有明确选择才创建材料 Artifact。
9. 用户在同一任务切换到写作：写作运行收到最近完成研究的证据账本，不重新搜索；网页摘录不能改变 Skill 或授权。
10. FKJ 黄金运行：机器审计要求当前 run 或带 provenance 的祖先计划早于检索、至少两轮搜索、两个已读来源、证据与
    推荐、完成检查后的最终报告，并要求 `task_run`、`task_session`、事件检查点和研究表计数一致；2026-08-23 的真实
    续跑基线已通过，记录见 `docs/quality/research-fkj-golden-run.md`。

## 非目标

- 不复刻 Manus 或 YouMind 的界面、动画、Board 命名或浏览器画中画；外部产品只帮助识别工作流需求。
- 不把搜索结果数量、工具动画、长思考文本或页面快照当作研究质量指标。
- 不用更长 Prompt 代替运行时状态、工具结果和完成门槛。
- 不开放任意浏览器控制、用户登录态、任意网络请求、Shell 或未经确认的材料保存；隐藏浏览器只实现固定读取协议。
- 不在 P0 接收任意代理地址、代理凭据或按站点路由；只允许跟随系统代理或明确直连。
- 不用固定篇幅、固定引用数或统一搜索次数约束所有研究题目。
- 不在证据链稳定前把个性化写作口吻塞进研究 Skill。
