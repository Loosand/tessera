# ADR-0001：内容存储实验基线与评审门槛

> 代码源头：`apps/desktop/src/main/content-library-service.ts`、
> `packages/database/content-domain-repository.ts`、`packages/ai/src/server/content-domain-tools.ts`
>
> 状态：**提议 / 实验中，不是最终存储决策**。2026-08-22 暂以托管内容库混合方案验证统一创作流程；
> 数据库正文与完全开放外部工作区仍是平等候选。

## 背景

统一创作 Agent 需要从普通问答自然进入研究、写作、创建文档、建立项目和移动产物。数据库正文能简化业务操作，
外部工作区能最大化用户所有权；当前无法只凭实现成本判断最终方案。为了先验证交互而不制造不可逆迁移，实验选择
普通 Markdown 作为正文事实源、SQLite 作为控制层，并用后端无关的 Project、Document、Artifact 和 Operation 契约
隔离具体存储。

## 当前实验决定

- 用户显式选择一个可撤销授权的内容库根目录；应用建立可见的“未归档”和普通项目子目录。
- 已批准正文只写入 Markdown；SQLite 保存内容库授权、工作区来源、索引、资源关系、Artifact 和操作审计。
- 模型只调用稳定 ID 驱动的领域工具，不获得绝对路径、任意文件系统、覆盖、删除或 Shell。
- 创建文档、创建项目和移动文档使用 AI SDK 标准工具审批；移动在执行前检查全部冲突，失败时恢复磁盘动作。
- 撤销内容库授权不删除任何用户文件；更换最终适配器不得改写核心对话和工具 Part 协议。

这只是实验基线。它不授权把数据库正文或完全外部工作区标记为淘汰，也不授权建立 Markdown/数据库正文双写。

## 三个候选的统一评审

| 指标 | 采集方式 | 托管混合方案当前证据 | 数据库正文要证明 | 完全外部工作区要证明 |
| --- | --- | --- | --- | --- |
| 首次设置成本 | 从首次创建请求到可写目标就绪的时长、点击数、放弃率 | 需一次目录选择；设置页可更换/撤销 | 是否可做到零设置且仍有清晰导出 | 多目录授权是否不会造成高摩擦 |
| 端到端成功率 | 固定场景完成率及失败阶段 | 领域服务自动测试覆盖创建、项目、移动 | 事务失败和迁移恢复 | 跨目录权限、移动和外部变化 |
| 冲突与恢复 | 重名、外部编辑、索引失败、崩溃演练 | 重名移动保持来源/目标不变；正文磁盘优先 | 多端并发、记录版本与恢复 | 文件监控、符号链接和跨卷移动 |
| 用户所有权 | 脱离 Tessera 的读取、编辑、备份、Git 能力 | Markdown 可直接打开；撤销不删文件 | 完整导出、可读备份和灾难恢复 | 天然成立，但需稳定索引和关系恢复 |
| 多端与协作 | 同步延迟、冲突数、离线行为 | 取决于用户同步目录，尚未验证 | 数据同步优势能否覆盖锁定成本 | 各平台目录授权与同步差异 |
| 迁移成本 | 双向导入导出的正确率和耗时 | 后端无关 ID/工具已建立，适配器替换待验证 | Markdown/附件/关系完整导入导出 | 从任意结构归一化和撤销登记 |
| 运维复杂度 | 故障面、数据修复工具和代码量 | 文件 + SQLite 协调仍需恢复演练 | 数据库备份、升级和附件存储 | 权限、监控、跨目录和路径差异 |

所有方案必须复用同一组验收：普通问答 → 联网研究 → 写作 Skill → 创建文档 → 创建项目 → 移动文档 →
重启恢复。不得为某个候选更换用户任务或降低安全要求。

## 当前证据与待采数据

已获得的自动化证据：未归档文档创建、项目创建、安全移动、目标冲突无副作用、授权撤销不删除正文、稳定
Artifact/资源关系和项目操作审计。

### 2026-08-22 dev Electron 实验记录

在隔离的临时内容库中使用当前 dev Electron 和真实已配置模型完成了以下路径，未打开已安装的旧打包应用：

- 自动对话可以在单步、零工具时直接回答；研究任务记录到 `research`、高推理、联网和 2 次搜索工具调用。
- 写作请求自动解析为 `writing`，经标准工具审批在“未归档”创建《Madeline：与自己和解的攀登》；Artifact、
  Document、Project 和 output/scope 资源关系写入 SQLite，Markdown 正文只存在于内容库。
- 原任务继续创建“Madeline 专题”、移动该 Artifact 并检查项目。`create-document`、`create-project`、
  `move-documents`、`inspect-project` 四条操作均为 `applied`；目标项目最终只有 1 篇 1106 字节 Markdown，
  “未归档”没有重复副本，Artifact ID 与 Document ID 在移动前后保持不变。
- 五个相关 run 均保存了完成原因、步骤/工具计数、首输出和总耗时；可见的缓存读 Token 已随 run 保存。
  AI SDK DevTools 能查看同一 run 的模型、reasoning、搜索和工具时间线。
- 从任务 Artifact 打开移动后的文档时，原 Task 的消息、reasoning、工具历史和输入状态继续显示在右侧栏；
  当前文档以可移除附件加入，侧栏可以切换项目历史或新建任务，输入区固定在底部。
- 验收发现“普通打开托管项目会覆盖 `storage_kind` / `content_library_id`”的控制层缺陷；仓储现已只在调用方
  显式提交存储元数据时更新这两个字段，并增加回归测试，避免托管项目被降级为外部工作区。

这轮记录证明当前混合原型可以跑通核心创作和整理闭环，但不能代替真实用户设置成本、多端、导入导出、
长期外部编辑、数据库丢失后的关系恢复和三种候选的同条件对照数据。

## 最终决策门槛

只有在三个候选都完成统一端到端场景、备份/恢复、导入/导出和至少一轮真实使用观测后，才能把本文状态改为
“接受”或由新的 ADR 取代。最终 ADR 必须明确：权威正文、事务边界、离线行为、附件、备份、恢复、导出、旧数据
迁移和退出路径。在此之前继续保持探索标识，不删除外部工作区能力，不把正文迁入 SQLite，也不做双写。
