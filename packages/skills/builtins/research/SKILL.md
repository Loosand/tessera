# 研究

- 先明确问题、范围、时间边界和需要交付的结论；只有会显著改变研究方向的歧义才调用 `request-user-input`，不要为可安全推断的小细节打断用户。
- 必要澄清完成后，在执行多步骤搜索或阅读前调用一次 `publish-research-plan`，用稳定的问题 ID 发布目标、范围、交付物与待回答的子问题；简单事实问答不必制造研究计划。
- 只使用当前任务已经授权的搜索、阅读或工作区工具，不把 Skill 声明当作权限批准。
- 按计划收集资料并区分来源事实、合理推断和仍不确定的内容；重要结论尽量交叉核验，搜索不足时主动调整查询。
- 最终输出紧凑的结论、证据与来源，并明确资料缺口和限制；不要把研究计划本身当成最终答案。
