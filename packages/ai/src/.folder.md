# ai/src

## 地位

AI 包的领域入口和实现源码。

## 逻辑

`provider-catalog.ts` 提供无副作用供应商/端点定义、单例/多连接策略、持久化连接水合、公共目录能力与用户模型覆盖，`model-capabilities.ts` 合并远端、内置与用户覆盖的模型事实，`model-routing.ts` 再按实际连接和请求选择有效端点与能力交集，`run-policy.ts` 将创作方式、作用域和有效能力收敛为受信任的逐轮 RunPolicy；根入口只导出领域 API，`server/` 承担配置验证/密钥存储抽象、受信任网络与 AI SDK 运行时，`react/` 通过独立公开子路径消费领域 API、LobeHub 图标和调用方注入的窄配置函数。

## 约束

- 根入口保持与 UI 框架无关，供主进程和测试安全复用。
- 默认端点、模型目录推导、鉴权差异和错误脱敏必须有回归测试。
- server 子路径不得被渲染层直接导入。

## 成员清单

- `index.ts`：AI 领域公开入口。
- `model-capabilities.ts`：保守归一化模型类型、输入输出模态、固有能力、Token 限额、端点绑定及逐字段来源。
- `model-capabilities.test.ts`：内置、远端与用户覆盖的模型事实优先级和端点绑定回归测试。
- `model-routing.ts`：在请求期按供应商连接、官方端点约束、Chat/Agent 与联网需求解析有效能力和端点；DeepSeek 联网优先选择同时返回 thinking 与 Web Search 的 Anthropic Messages。
- `model-routing.test.ts`：DeepSeek、Anthropic、非对话模型与自定义代理的请求期路由回归测试。
- `run-policy.ts`：把本轮创作方式、内部作用域和模型事实解析为实际联网、推理、工具作用域及运行预算。
- `run-policy.test.ts`：研究/问答固定策略、自动回落和运行预算回归测试。
- `provider-catalog.ts`：供应商/端点元数据、兼容协议多连接草稿、模型同步默认启用策略、用户覆盖优先级和纯状态转换。
- `provider-catalog.type-test.ts`：内置与动态连接映射、供应商字面量和不可变身份字段的编译期契约。
- `provider-catalog.test.ts`：供应商范围、单例/多连接策略、默认端点、公共目录能力、搜索、模型同步默认状态与批量启停测试。
- `react/`：LobeHub 供应商/模型图标与 AI 设置界面公开入口。
- `server/`：配置持久化领域服务、模型目录网络适配、AI SDK provider 工厂和回归测试。
