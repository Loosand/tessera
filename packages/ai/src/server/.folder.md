# ai/src/server

## 地位

AI 包中仅供受信任主进程使用的网络与 AI SDK 运行时边界。

## 逻辑

`api-key-validation.ts` 统一约束供应商密钥为可安全写入鉴权请求头的可打印 ASCII；根目录 `provider-input-validation.ts` 统一 API 根地址与模型 ID 边界；`provider-config-service.ts` 通过依赖注入的配置仓储与安全存储完成协议/连接校验、旧模型能力迁移、统一模型事实持久化、加密密钥解析和公开配置隔离；`model-discovery.ts` 根据协议推导可选模型目录，公共目录省略凭据、受保护目录设置鉴权并归一化响应，404/405 作为目录不受支持而非连接失败；`ai-sdk-runtime.ts` 只执行请求期解析器已明确选择的生成端点，DeepSeek V4 原生联网默认走同时支持 thinking 与 Web Search 的 Anthropic Messages，Responses 保留为端点回退并显式声明推理模型语义，普通请求与研究 Skill 使用不同的有界搜索额度；`task-agent.ts` 再以 AI SDK `callOptionsSchema` / `prepareCall` 消费受信任 RunPolicy，保留具体 ToolSet 类型并统一收窄工具、推理、安全护栏和内置/主进程复核用户 Skill instructions，每步出站前由 `context-budget.ts` 生成无正文 ContextManifest 并阻断已知超预算输入；显式研究额外读取持久化领域进度，在首次搜索前只允许计划/核心消歧，首次深读后若尚无证据则优先批量登记并保留重新深读或如实部分完成的逃生路径，证据门槛满足后先推荐证据链来源再冻结覆盖，接近上下文感知循环保险丝时强制完成检查，并在领域完成后固定保留一个无工具最终文本步骤；研究不设置累计 Token 或应用侧单步输出额度。`agent-runtime.ts` 在持久化消息上先运行模型历史投影：旧助手轮次只保留可见正文，当前审批/自动续轮和显式失败续跑才保留已终止工具 Part；随后使用 `InferAgentUIMessage<typeof agent>` 约束投影结果，交由 `createAgentUIStream` 内部标准执行 `validateUIMessages` 与 `convertToModelMessages`，不维护平行供应商转换协议；工作区 Markdown 工具还要经过当前请求相关性门禁，写作运行可以接收最近完成研究的受限证据交接。流异常在字符串化前保存安全类别/HTTP 状态，402 明确识别为不可重试的余额错误，400/409/422 提示已隔离失败历史；自有领域工具只通过显式可信错误类型公开可操作文案，未知工具和供应商载荷继续脱敏；供应商原生搜索预算耗尽按标准 Tool Error Part 公开，兼容端点误报顶层错误但随后给出完整正文时恢复为正常完成。最终正文完成后，`follow-up-questions.ts` 通过同一模型执行有独立短超时的结构化非关键后处理，生成持久化引申问题；失败不会把主回答改成失败，用量与耗时则并入同一 task run。全部运行从 `onStepEnd` / `onEnd` 原生生命周期归一化完成原因、Token、缓存、步骤/工具计数和性能指标。所有任务共用结构化交互工具、托管内容库领域工具与 `ToolLoopAgent`；有工作区授权且当前请求相关时，同一工具循环额外组合受限 Markdown 工具，MCP 工具按独立信任配置组合；显式 Markdown 附件在进入模型前转换为带材料边界的文本，持久化历史仍保留可见附件 Part。

## 约束

- API Key 不记录、不写入错误消息；持久化和出站请求前必须校验为不含空格、控制字符或非 ASCII 字符的可打印 ASCII，持久化时只允许保存平台安全存储生成的密文，公开配置只返回是否已配置。
- 模型目录地址由 API 根地址推导，界面不得要求用户填写独立 models URL。
- 模型目录请求允许省略 API Key；适配器只在存在密钥时发送鉴权头，是否允许匿名访问由远端服务决定。
- 兼容协议允许多条具名连接，官方供应商保持单例；运行时必须以 `configId` 解析具体凭据。
- 兼容端点返回目录 404/405 时必须允许手动模型 ID，不能据此判定生成接口不可用。
- 只允许 http(s) 端点，禁止 URL 内嵌账号或密码，网络请求必须有超时。
- 供应商原生适配器优先；OpenAI 兼容服务与 OpenRouter 使用 AI SDK compatible adapter。

## 成员清单

- `api-key-validation.ts`：配置、目录发现与生成运行时共用的 API Key 长度和请求头安全字符校验。
- `index.ts`：服务端子路径公开入口。
- `provider-config-service.ts`：协议与连接实例验证、旧模型能力迁移、统一模型事实归一化、仓储/安全存储抽象、加解密与连接凭据解析。
- `provider-config-service.test.ts`：跨实例恢复、旧配置迁移、兼容协议多连接、官方单例、密钥格式与隔离、保留/移除和删除配置测试。
- `model-discovery.ts`：模型目录 URL、鉴权、请求、安全数值/模型 ID 归一化和错误脱敏。
- `model-discovery.test.ts`：模型发现协议、密钥请求头校验、鉴权回退与目录不受支持降级的回归测试。
- `ai-sdk-runtime.ts`：五类供应商和显式端点到 AI SDK `LanguageModel` 的映射、搜索额度约束与原生联网工具注册。
- `ai-sdk-runtime.test.ts`：生成请求的密钥校验、真实 provider factory 映射和有界搜索额度测试。
- `chat-runtime.ts`：统一 Agent 复用的消息输入约束、显式 Markdown 附件材料化、可稳定重放的模型历史投影、搜索额度、嵌套供应商错误类别/HTTP 状态脱敏及公开增量裁剪；不再提供独立 Chat 运行入口。
- `chat-runtime.test.ts`：验证文档材料边界、模型历史投影、工具/引申问题增量、搜索额度和错误文案只按共享契约公开。
- `follow-up-questions.ts`：在已完成正文之后用同一模型生成 2–4 个结构化引申问题，并把短调用用量合并进主运行指标。
- `follow-up-questions.test.ts`：验证问题清洗去重、短调用约束与运行指标合并。
- `context-budget.ts`：按模型事实、当前步骤 instructions、会话、工具结果和活动工具生成脱敏 ContextManifest，并在已知超出安全输入预算时于供应商调用前停止。
- `context-budget.test.ts`：中英文 Token 启发式、分项预算、未知上限兼容和超预算阻断回归测试。
- `agent-runtime.ts`：组合供应商原生搜索、搜索预算耗尽续答、主进程研究领域服务、按请求相关性开放的工作区读写、MCP 动态工具、标准人工审批、供应商错误分类、Agent 指令与资源上限，先投影可稳定重放的模型历史，再以 Agent 推导 UIMessage 并由 AI SDK 标准转换，裁剪网页正文并隐藏完成检查前的模型进度旁白后，在正常最终正文后追加类型化引申问题，实现统一 `AgentRuntime` 端口的 AI SDK 工具循环。
- `agent-runtime-search-budget.test.ts`：合成兼容端点搜索额度顶层错误、额度后正文和尾部错误，验证降级为 Tool Error 后正常完成。
- `agent-runtime.test.ts`：写入工具根对象 JSON Schema、create/update 条件、搜索预算工具错误续答和 MCP 强制人工审批回归测试。
- `task-agent.ts`：保留具体 ToolSet 类型，通过类型化 call options 动态配置无工作区和工作区任务共用、带研究阶段工具门禁、稳定 Telemetry 标识与 AI SDK 原生生命周期指标归一化的 ToolLoopAgent。
- `task-agent.test.ts`：RunPolicy Schema、conversation/workspace-read/workspace-write 工具收窄、研究计划/保险丝/完成状态与生命周期指标回归测试。
- `research-tools.ts`：主进程研究服务到计划、网页深读、单次最多 12 条的批量证据登记、证据链来源推荐与完成检查工具的窄适配，并从公共消息裁剪网页正文。
- `research-tools.test.ts`：研究工具集合、批量证据上限与正文仅进入当前模型上下文、不写入公共消息的回归测试。
- `skill-instructions.ts`：按需加载任务所选内置 Skill，或接收主进程已复核且 ID 匹配的用户 Skill，并装配不提升权限的 AI SDK 共用 instructions。
- `skill-instructions.test.ts`：问答空选择、内置/用户单 Skill 注入、用户正文复核和权限边界回归测试。
- `task-interaction-tools.ts`：Chat/Agent 共用的核心语义消歧暂停工具、每个用户请求一次的暴露限制与 Research Skill 结构化计划工具。
- `task-interaction-tools.test.ts`：单问题/计划 Schema、无执行暂停语义、每请求一次限制和 Skill 工具暴露边界测试。
- `content-domain-tools.ts`：主进程混合内容服务到 AI SDK 项目/Artifact 查询、创建、检查与安全移动工具的窄适配，并为所有写入启用标准审批。
- `content-domain-tools.test.ts`：领域输入不接受路径、只读查询直接执行和写操作强制审批测试。
- `../intent-routing.ts`：自动模式下只对明确的研究/写作请求收窄内置 Skill；一般显式选择优先，已完成研究后的明确成稿/保存请求可从遗留 Research 交接给 Writing，普通问答和项目操作保持自动。

## 触发器

供应商协议、鉴权方式、AI SDK 适配器、服务端导出或成员变化时更新本文。
