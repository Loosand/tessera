# ai/src/react

## 地位

基于 AI 领域目录和 Tessera 设计系统的可复用 React 界面层。

## 逻辑

`@lobehub/icons` 的精选品牌组件按供应商键和完整模型 ID 分别异步加载，未知模型回退到中性头像；统一模型头像可在设置与任务输入之间复用，且不会把图标包的完整品牌目录带入发行包。设置界面由桌面端注入类型化连接和研究网络模式读写函数；AI 设置异步读取主进程持久化的系统代理/直连选择。供应商设置由纯状态转换、连接导航/总览、模型列表和详情编排分层协作，使用判别式选择明确区分全部连接与具体 `configId`，并允许兼容协议创建多条具名连接。模型目录以语义图标在行尾呈现上下文、视觉、推理、工具、结构化输出与端点联网能力，纵向编辑器分别维护模型事实和只读端点投递，模型同步、增删、启停和编辑成功后立即保存；目录 404/405 作为不支持目录的中性状态呈现并保留手动模型入口；`use-electron-chat.ts` 通过窄桥只把内部作用域、Skill、资源和模型选择连同 AI SDK React 状态机映射到主进程流式事件，不传递联网或推理能力开关；它只为已持久化任务尝试挂载恢复，区分页面订阅断开与用户显式取消，并按 task ID、请求 ID 和连续事件序号过滤重复、缓冲乱序、显式报告恢复缺口。失败重试或已完成副作用回复重生成时，它只把已完成 Tool Part 补到新 request，避免重放写入或未知 MCP 副作用；取消本地 `ReadableStream` 只释放订阅，且不会重复关闭 controller。完整 AI SDK `UIMessage` 工具/审批/引申问题历史与可持久化任务消息保持往返，包含仅限本机的反馈 metadata 与区分供应商原生工具的 `providerExecuted`；运行失败先写入带 code/phase/retryable 的 `data-task-error` Part 再触发 AI SDK 原生 error 状态，工具输入/执行失败先写入带稳定 code 和 tool 标识的 `data-tool-error` Part 再保留 AI SDK 标准 Tool Part 错误状态，避免重复错误卡片并支持重启诊断。消息元数据先经类型守卫收窄，并只在人工审批或 `request-user-input` 已获得结果时自动提交下一轮。

## 约束

- 只使用 `@tessera/design-system` 暴露的交互原语。
- 不直接访问 Electron、文件系统、数据库或浏览器持久化存储。
- 新输入的明文密钥只允许短暂存在于组件内存；持久化后组件只接收 `apiKeyConfigured`，网络调用由桌面端注入的类型化 IPC 函数完成。
- 模型图标必须从完整模型 ID 推导且保留未知模型回退，不维护易过期的本地品牌 SVG 副本。
- 品牌图标必须直接导入精选组件并拆分为异步 chunk，禁止通过包根动态导入完整图标目录。

## 成员清单

- `index.ts`：React 子路径公开入口。
- `ai-model-icon.tsx`：按完整模型 ID 从精选品牌规则异步解析并统一呈现模型头像。
- `ai-model-icon.test.ts`：验证常用模型品牌映射和未知模型的中性回退。
- `ai-settings.tsx`：与连接配置解耦的 AI 可用性、工具建议权限，以及由主进程注入的研究网页系统代理/直连界面。
- `ai-provider-settings.tsx`：水合连接草稿并编排配置保存/删除、兼容协议连接创建、目录同步和供应商详情状态。
- `provider-navigation.tsx`：按需加载精选供应商品牌图标，呈现可搜索连接目录、全部连接总览与复用状态标记。
- `provider-model-list.tsx`：呈现模型分组、Token/模态/推理/工具/结构化输出/端点联网能力标记与行级操作。
- `provider-settings-state.ts`：供应商设置共用的判别式选择、连接视图和持久化配置/界面草稿纯转换。
- `provider-settings-state.test.ts`：判别式选择、连接枚举和配置/草稿转换回归测试。
- `model-editor-dialog.tsx`：以纵向表单和上下文滑块编辑模型类型、输入输出模态、固有能力和 Token 限额，并只读呈现供应商端点与原生联网绑定。
- `task-ui-message.ts`：任务 metadata/data 与 AI SDK `UIMessage` / Tool Part 的单一类型边界，统一使用 SDK 守卫识别工具并读取名称。
- `use-electron-chat.ts`：AI SDK React `useChat` 到 Electron IPC 事件流的可独立验证 Transport，只透传任务作用域、Skill、资源和模型选择，由主进程解析实际 RunPolicy，并处理已持久化任务恢复、重新生成 provenance、失败/副作用回复的已完成工具结果续跑、草稿跳过恢复、重复过滤/乱序缓冲/缺口失败、订阅断开、取消流安全收口、幂等显式取消、等待输入识别、完整工具/引申问题/本地反馈历史往返、版本化消息内失败与问答/审批后自动续轮。
- `use-electron-chat.test.ts`：合成正文与工具完整增量序列，验证模式、任务标识和当前文档透传、失败或副作用回复续跑、草稿不恢复、断开与幂等取消边界、重连事件重复/乱序/缺口处理、等待输入/选择性自动续轮，以及思考/来源/引申问题/工具/模型与反馈元数据和部分正文后版本化失败的持久化往返。

## 触发器

React 公开组件、品牌资源、交互状态或成员变化时更新本文。
